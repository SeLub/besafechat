feat: implement seed-based account recovery with cloud and self-custody options

## Overview
Implemented complete BIP39 seed-based account recovery system with two modes:
- Cloud Recovery: Argon2id-encrypted seed stored in S3, recovery via @username + password
- Self-Custody: Local seed storage, full user control

## Backend Changes

### Storage Module
- Added `SeedBackupController` with endpoints:
  - `POST /storage/auth/upload` - Upload encrypted seed to S3 (authenticated)
  - `GET /storage/auth/download` - Download own seed (authenticated)
  - `GET /storage/auth/download/by-username/:username` - Public recovery endpoint
  - `DELETE /storage/auth/delete` - Delete seed backup
- Integrated with `UsernameModule` for username-based recovery
- S3 storage path: `users/{userId}/auth/seed.enc`

### Seed Backup Format
```json
{
  "encrypted": "base64_encrypted_seed",
  "salt": "base64_random_salt",
  "iv": "base64_initialization_vector",
  "authTag": "base64_auth_tag",
  "version": 3,
  "kdfParams": {
    "algorithm": "argon2id",
    "timeCost": 3,
    "memoryCost": 65536,
    "parallelism": 4,
    "hashLength": 32
  },
  "publicKey": "base64_ed25519_public_key",
  "createdAt": 1765210972328
}
```

## Frontend Changes

### Cryptography
- Replaced `bip39` with `@scure/bip39` (browser-native, no polyfills)
- Added `@noble/hashes` for Argon2id and SHA-512
- Configured `@noble/ed25519` with SHA-512 for key derivation
- Implemented Argon2id key derivation (3 iterations, 64MB RAM, 4 threads)
- AES-256-GCM encryption for seed storage

### Account Creation Flow
1. Username Selection (mandatory, 5-32 chars, real-time availability check)
2. Security Level Selection (Cloud Recovery / Self-Custody)
3. **Cloud Recovery**: Password creation → Auto-upload to S3
4. **Self-Custody**: Seed display → Seed verification → Account created

### Recovery Flow
- **By Password**: Enter @username + password → Download from S3 → Decrypt → Login
- **By Seed**: Enter 12-word seed phrase → Derive keys → Login

### UI Components
- `UsernameSelection` - Real-time username validation with 500ms debounce
- `MethodSelection` - Cloud vs Self-Custody choice
- `SeedDisplay` - 12-word seed with copy/download
- `SeedVerification` - 3 random word verification
- `PasswordCreation` - Password strength meter (8+ chars, uppercase, lowercase, number)
- `RecoveryOptions` - Username + password or seed phrase input

### IndexedDB Schema
- Added `seeds` table for temporary seed storage during cloud backup
- Updated `privateKeys` table with `source` field ('cloud' | 'seed')

## Security Features
- **Argon2id KDF**: 3 iterations, 64MB memory, 4 threads (1000x slower than PBKDF2 on GPU)
- **Random salt**: 32 bytes per user, stored in S3 (not secret)
- **AES-256-GCM**: Authenticated encryption for seed storage
- **No pepper**: Argon2id parameters provide sufficient protection against offline attacks
- **Username-based recovery**: Public endpoint without authentication (no catch-22)

## Technical Decisions
- **@scure/bip39 over bip39**: Browser-native, smaller bundle, no Buffer polyfill needed
- **Argon2id over PBKDF2**: Better GPU resistance, allows shorter passwords (8 vs 16 chars)
- **hash-wasm over argon2-browser**: Better Vite compatibility, smaller size (~50KB vs ~120KB)
- **Username-based recovery**: Solves authentication paradox (can't login without seed, can't get seed without login)
